# 2026-08-25 连续执行 handoff 路径问题

## 现象

第三格 `rep1_random_common_mix_train17` 的 ASDiv、MultiArith、SVAMP 均已完成，OOD v3 审计也已经输出 `PASS`。一次性 handoff 脚本随后执行：

```bash
sha256sum -c "$run3/audit/formal_cell_audit.sha256"
```

但 sidecar 内只记录相对文件名 `formal_cell_audit.json`。命令当时的工作目录是仓库根目录，而不是 `$run3/audit`，因此 `sha256sum` 报告找不到文件并使 handoff 按 `set -e` 安全停止。

证据文件本身没有损坏。随后在审计目录中执行校验，两个审计均通过：

```bash
(
  cd "$run3/audit"
  sha256sum -c formal_cell_audit.sha256
  sha256sum -c ood_audit.sha256
)
```

证据包的 `.sha256` sidecar 也遵循同样规则，必须在证据包所在目录执行 `sha256sum -c`。

## 后续固定规则

1. 所有只写文件名的 SHA-256 sidecar，都在 artifact 所在目录执行 `sha256sum -c`。
2. 自动 handoff 失败后先核对科研产物和审计状态，不重新运行已经完成的 GPU 生成。
3. sidecar 路径错误属于编排层故障，不修改冻结模型、训练、评估或统计参数。
4. 连续控制器内部使用 Python 绝对路径重新计算哈希，不依赖 shell 当前工作目录。
5. 新 handoff 脚本必须用一个临时目录下的“artifact + 相对 sidecar”做端到端测试。
