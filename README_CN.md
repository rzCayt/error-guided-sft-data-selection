# 大模型后训练数据选择：一项受控实验研究

[English README](README.md) · [结论与边界](CLAIMS_AND_LIMITATIONS.md) · [复现说明](REPRODUCE.md) · [研究时间线](docs/research_timeline.md)

## 研究问题是什么？

本项目研究一个具体问题：

> 在训练样本数量、回答监督词元和数据组成保持一致时，有目标的数据选择方法，是否真的比匹配随机选择更有效？

**回答监督词元**是回答中真正参与训练损失计算的 token，不包括提示词和填充 token。**候选效用**是指：用一个候选样本对模型进行一次标准化更新后，独立效用验证集上的损失下降了多少。**状态依赖**是指：同一个样本的估计训练价值，会不会随着模型已经训练到的参数状态而改变。

当前实验研究的是一项冻结的 RDS 目标选择策略、Qwen2.5-1.5B Base、只在回答部分计算损失的 LoRA 监督微调，以及算术推理任务。它是对这个具体设置的受控研究，不是对所有数据选择方法的普遍结论。

## 已经完成了什么？

主要实验完成了 24 个经过独立审计的训练与评估格子：

```text
2种选样方法 × 4份独立构造的名单 × 3个训练随机种子
= 24组实验
```

每份名单恰好包含 500 条样本。RDS 和匹配 Random 使用相同的模型、LoRA 配置、优化协议、样本数量、回答监督词元预算以及“数据来源 × 回答长度”组成。每个完成格子都保存冻结配置、选样清单、训练日志、adapter 保存与重新加载证明、原始生成、解析指标和独立审计结果。

在这组实验之前，项目还测量了 96 个 Tulu 候选的单步效用，并完成 48 个 GSM8K 域内候选的边界检查。Tulu 实验通过了当时预注册的筛选门槛，GSM8K 域内检查没有通过。这些只是候选级证据，不能直接证明整批数据训练有效。

## 主要结果是什么？

下表中的规范数字由 [`results/public_summary/main_results.json`](results/public_summary/main_results.json) 生成。正数表示 RDS 更高。

| 评估指标 | RDS相对Random的差异 | 95%区间 | 当前判断 |
|---|---:|---:|---|
| GSM8K数值准确率 | +0.480个百分点 | [-0.954, +1.889] | 证据不足 |
| 三个分布外任务平均准确率 | -0.094个百分点 | [-1.316, +1.149] | 证据不足 |

![下游差异点估计与95%区间](figures/fig_main_effects.png)

当前实验没有发现 RDS 相对匹配 Random 的可靠准确率提升。但两个区间都同时包含具有实际意义的正效果和负效果，因此也不能说 RDS 已经无效，或两种方法已经等效。这些结论只适用于当前模型、训练预算、候选池和算术任务。

三个分布外任务是 SVAMP、ASDiv numeric 和 MultiArith。各任务结果及重新抽样训练种子的敏感性分析统一保存在规范 JSON 和自动生成的 CSV 中，不在多个文档里重复维护。

## 这些结果意味着什么？

项目观察到了“局部筛选信号”和“下游训练收益”之间的缺口。在 Tulu 候选池中，错误条件化分数与单步候选效用的偏 Spearman 相关为 0.228，单侧置换检验值为 0.073，达到了当时冻结的筛选门槛；GSM8K 域内边界检查没有通过。更重要的是，Tulu 中有限的候选级信号没有在 500 条样本联合训练后转化成稳定收益。

![候选级筛选与集合级训练结果](figures/fig_candidate_to_set_gap.png)

这是因为“单独判断一个样本是否有用”和“把一批样本放在一起训练”并不是同一个问题。现在至少还有三种可能原因：

1. 候选效用本身测得不够稳定；
2. 模型参数状态改变后，同一样本的价值也会改变；
3. 单独有用的样本组合后会发生重复、冲突或互补。

项目还检查了一个冻结的“训练回答组成解释”，试图解释严格格式行为的差异。没有任何特征同时通过预先规定的来源敏感性和多重比较门槛，因此该路线已经停止，也没有追加 GPU 重训。这只是一次没有通过门槛的机制检查，不能推出“格式永远不重要”。

## 目前仍然不知道什么？

已完成证据不能支持以下结论：

- RDS 普遍无效；
- RDS 与 Random 已经等效；
- 错误条件化相对 all-query 提供了新增信息；
- 候选效用能够稳定重复测量；
- 状态依赖解释了当前下游结果；
- 在最终 adapter 上进行局部探测，能够还原历史优化轨迹。

24 格实验只是一个受控 pilot：模型只有一个、监督预算只有一个、任务主要是算术推理。更广泛的模型规模、任务类型、训练预算和外部 selector 结论都需要新的确认实验。

## 下一步实验是什么？

下一阶段先检查：在同一个固定模型状态下，候选效用能不能稳定测量。只有测量可靠，才会比较标准 zero-LoRA 状态和已经训练完成的 LoRA adapter 状态之间，候选价值排序是否发生变化。

```text
固定状态下测量不可靠
→ 研究怎样估计并降低效用测量噪声

固定状态下可靠，但训练后排序改变
→ 研究什么时候需要重新估值

固定状态下可靠，而且训练后仍稳定
→ 研究样本组合时的重复、冲突和互补
```

![State Dependence v3决策流程](figures/fig_state_dependence_decision.png)

**State Dependence v3 当前状态：CPU 合同、候选面板冻结、重合检查和预检已经完成；GPU qualification 和正式测量尚未开始。** 冻结面板包含 48 个没有被四个初始目标 adapter 训练过的候选。另有 14 个存在直接训练暴露的候选已经在冻结前移除。

## 怎样验证结果？

公开版的轻量验证命令如下：

```bash
python -m pip install -e ".[dev]"
python scripts/reproduce_public_summary.py --check
python scripts/verify_public_release.py
python -m pytest -q
python -m ruff check .
```

安装后的第一个脚本会从审计证据重新计算公开摘要，并与仓库中的 JSON、CSV 和 Markdown 表格逐项比较。发布验证脚本会检查必需文件、证据哈希、README 数字、当前/历史标记、密码与本机绝对路径、受限产物和 Markdown 链接。CPU 验证、GPU 复现与预期输出的区别见 [`REPRODUCE.md`](REPRODUCE.md)。

仓库不提交大型原始生成、adapter 权重、云端凭据和受限数据正文。公开证据只包含允许公开的汇总、ID、哈希、冻结配置和审计记录。

## 局限与AI协助

主要局限包括：单一模型系列和规模、单一 500 样本预算、单一候选池、以算术为主的评估、高度重合的 RDS 名单重复，以及 State Dependence v3 尚未完成。 当前[实验完整性检查](EXPERIMENT_AUDIT.md)保持 WARN：Git 中没有保存每格原始生成和 adapter，而且本轮没有可用的独立外部 reviewer 后端。完整结论边界见 [`CLAIMS_AND_LIMITATIONS.md`](CLAIMS_AND_LIMITATIONS.md)。

LLM 工具对代码脚手架、调试、文档和对抗审阅提供了大量协助。项目负责人选择研究问题，授权协议冻结与实验执行，检查证据，决定研究路线继续或停止，并对公开结论负责。本仓库不会把全部代码表述成“完全不借助 AI 独立编写”。详细说明见 [`AI_ASSISTANCE.md`](AI_ASSISTANCE.md)。
